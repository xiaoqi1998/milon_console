## 修复：`/api/read` 系列报错 "address must be 20 bytes"

### 背景
调用 `POST /api/read/multi`（含 `ReadContractMulti`）等接口时，若 args 中地址类型字段（如 `holder`）传入非法的 base58 字符串（截断/缺字符/垃圾字符串），会得到 500 + 迷惑性错误 `address must be 20 bytes`。根因在 `gosdk-develop/provider/provider.go` 的 `serializeAddress`：string 分支要求 base58 解码后严格 20 字节，否则直接返回无上下文错误。

### 修改内容（方案 C：两处修复）
1. **`gosdk-develop/provider/provider.go`**
   - 新增 `Provider.NormalizeArgs(instructionName, args)` 公开方法：按 IDL 指令定义把 `Address`/`Signer`（含 `option<Address>`、`vec<Address>`）类型的 string 值提前归一化为 `crypto.Address`，失败返回清晰错误（含输入串和期望说明）。
   - 新增辅助函数 `normalizeAddressValue` / `parseAddressValue` / `tryParseAddressString`。
   - `encodeInstruction` 序列化前调用 `normalizeAddressValue` 做兜底（覆盖所有 `pd.Encode` 调用路径，包括 SDK 内部 `BuildAndViewSingleIx`）。
   - `serializeAddress` 的 string 分支改进：兼容 base58check 变体（21 字节 = version+payload，25 字节 = version+payload+checksum）；错误信息带上实际解码字节数。
2. **`handler/contract.go`**
   - `ReadContractMulti`、`dispatchSimulate`、`dispatchSubmit` 在 `pd.Encode` 前调用 `pd.NormalizeArgs`，地址校验失败返回 400（`ERR_INVALID_PARAMETER`）而非 500。

### 新增测试
`gosdk-develop/provider/normalize_addr_test.go`：覆盖合法 base58/hex、截断、过短、垃圾字符串、option、vec、非地址类型透传、`NormalizeArgs` 归一化。

### 验证
- `go build ./...`（主模块）通过
- `go test ./provider/`（gosdk-develop 模块）全部通过

### 备注
- 用户之前遇到的地址 `37ptHG4B6QsJ3AY1CG6fKMskWvSW` 查询账户返回 500 `account not found`，是链上无该账户所致（未激活/未发生交易），与本修复无关。
- 技术要点：milon base58 地址 = 20 字节原始地址直接 base58，无 Tron 式 0x41 前缀/校验和；但为兼容可能的外部地址格式，`tryParseAddressString` 容忍 21/25 字节 base58check 变体。

## 评估新版 SDK（Downloads/gosdk-develop (3)）对项目的破坏性影响

### 结论：新版 SDK 是破坏性重构，handler 层大量 API 被移除，不能直接替换

旧版（当前项目内置 gosdk-develop）依赖的 API 在新版中多数已删除：

**已移除（handler 直接用）**：
- `lib.NewTransactionWithParam` / `lib.NewTransactionFromBytes` → 改为 `lib.NewTransactionBuilder` + `lib.AccountSignatureBuilder` 链式 API
- `Transaction.SignIx/SignPayer/SignIxGas/SignIxAndPayer/SignIxes/SimulateSign*`、`ResolvePayer` → 全部移除
- `provider.Provider.NormalizeArgs`（今天刚修复并新增的方法）→ 新版不存在
- `Client.GetPdByIDLAppName` / `BuildAndViewSingleIx` / `BuildAndViewMultiIx` → 移除
- `milon.SimulateTransactionResult` → 改为 `milon.SimulateTxResult`

**改名/移动**：
- `provider/manager.go`(IDLManager) → `provider/registry.go`(IDLRegistry)；`GetProviderManager()` 返回类型改为 `*provider.IDLRegistry`
- `api/rpcResponse.go` → 移到 `lib/rpcResponse.go`

**新增**：
- `gen/` 目录：IDL 代码生成（gen.go + idl_gen.go，用 tools/idlgen 从 IDL JSON 生成指令对象，经 gen.BindAll 在 NewClient 时绑定）
- 新 RPC：`BatchGetResourcePathByHash`；新 IDL：`demo.idl.json`、`system.idl.json`、`randomness.idl.json` 扩展
- `helper/` 新增 CheckSimulateSuccess/CheckTxSuccess/listSigners
- 测试文件重组到各包 `test/` 子目录

### 处理建议
- 直接替换本地 gosdk-develop 会导致 handler/contract.go、faucet_handler.go、transaction_handler.go、view_handler.go 编译失败
- 需按新版 API 重写 handler 交易构建/签名逻辑（TransactionBuilder/SignWith/ApplySlots/SimulateSlots），或保留旧版 SDK
- 本次未做替换，仅完成评估。
