## Console 排查：account not found / 地址无效问题

用户反馈两个现象（console 调试页）：
1. `POST /api/write` 调 token.transfer 报 invalid address（from 填了占位符 `Milon1l1l...`）
2. `GET /api/accounts/:address` 查 `RqcF3sWkzLQAcJQaMsMxbJaiYM` 报 account not found

排查结论（重要认知）：
- **余额查询（Token.BalanceOf）与账户信息查询（Account.GetAccount）走不同 app**：token 合约 balances 有记录≠ account 合约有账户状态。account 状态需显式执行 `Account.Create/EnsureAccount/CreateMultisig` 才存在。
- **Console IDL 面板默认执行模式是 simulate（模拟不上链）**（`static/js/app.js` 中 `idlExecMode='simulate'`，每次打开方法强制重置为 simulate），必须手动切到「上链提交」走 `/api/write` 才真正上链。
- EnsureAccount 参数 `owner_pk` 是 **PublicKey 类型**（示例：`0x03a34b2f5d9c0e1a8e4f2b1d6a3c5e7d9f0b2a4c6e8d0f1a3c5e7d9f0b2a4c6e`），不能填地址。

本次最终根因：用户查询的地址 `RqcF3sWkzLQAcJQaMsMxbJaiYM` 本身就是**非法 base58**（26 字符，解码 19 字节，标准 milon 地址为 28 字符/20 字节）。服务重启后错误变为 `invalid base58 decoded length: expected 20, got 19`，实锤地址无效，与链无关。

用户提交的 EnsureAccount 交易 `13e27ed967954952eab2efc1eb17407882da15f1fd65a8fce5601c25097b7e19` 成功（state:1），创建的账户地址为 `2cb9FUuEobGuwF9wukU59ytKNdjz`（由 owner_pk=03a34b2f... 派生，ed25519，threshold=1），实测可查询成功。

## "生成的地址查账户信息报格式不正确"排查结论
- GenerateAccount 返回三字段：`address`=base58（28字符）、`publicKey`=hex（66字符）、`privateKey`=hex（64字符）。
- 用户若拿 `publicKey`/`privateKey`（hex）当 address 查询 → 报 `invalid base58 decoded length: expected 20, got 0`（acc2.json 里的 `got 19` 是地址被截断/复制不完整，19字节）。
- 用正确 base58 address 查询是正常的，链上无账户返回 `account not found`（业务错误，非格式错误）——本地生成的账户需先通过 EnsureAccount 或 faucet claim 上链创建才能查到信息。
- 前端 console 生成后地址框自动填 `d.address`（base58），正确；问题多出在用户手动复制字段或复制不完整。
