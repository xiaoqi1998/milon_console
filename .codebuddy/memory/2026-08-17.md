## /api/util/sign 接口使用问题
- 用户在 Web 控制台 POST `/api/util/sign`，`message: "编码"`，返回 400 `invalid hex message: encoding/hex: invalid byte: U+00E7 'ç'`。
- 根因：`handler/util.go:182` 用 `hex.DecodeString(req.Message)`，要求 message 是 **hex 编码**而非明文。`U+00E7 'ç'` 是字节 `0xE7` 被 Latin-1 显示出来的形态，对应 "编码" UTF-8 首字节。
- 正确用法：原文 "编码" → UTF-8 `E7 BC 96 E7 A0 81` → hex 字符串 `e7bc96e7a081` 作为 `message`。
- 文档来源：`API.md:1544-1568` 明确 `message` 为 "hex 编码"；启用需 `ENABLE_UTIL_SIGN=true`。
- 优化建议（用户未要求实施）：第 182 行可改为 `decodeMessageFlexible`，优先尝试 hex 解析，失败则按 UTF-8 字节处理，向后兼容。

## 已实施：message 支持 hex 或明文（2026-08-17）
- `handler/util.go`：新增 `decodeMessageFlexible(s string) []byte`，先尝试 `hex.DecodeString`，失败则按 UTF-8 明文字节处理。`SignMessage` 和 `VerifySignature` 均改为使用该函数。
- 注意：纯 hex 字符明文（如 `"deadbeef"`）有歧义，会被当作 hex 处理。
- `API.md`：更新 sign（§31）/verify（§32）的 message 字段说明，新增明文请求示例与歧义说明。
- `static/js/app.js`：sign/verify 的 bodyTemplate 提示改为 `message: 'hex编码或明文'`。
- `go build ./...` 通过，lint 无错误。
