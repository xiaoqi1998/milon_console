## Milon API Console multi_signer 报错排查

- 问题：IDL 方法 `nft.CreateUnique` 选择 multi_signer 模式并填写 signers 后，后端返回 `signers cannot be empty`。
- 根因：`static/js/app.js` 中 `buildIDLRequest` 对 signers 做 `JSON.parse` 时失败被静默 `catch`，导致请求体未携带 signers 字段。

- 涉及文件：`static/js/app.js`（第 4361–4410 行附近）。

## identity.Create invalid base58 string 报错排查

- 问题：`identity.Create` 模拟调用返回 `failed to parse public key from string: invalid base58 string`。
- 根因：`signatureMode.publicKey` 填的 hex 字符串 `02576c3b57c7bf586887dd1fc733f36f149680de26d968abd89df1c267fdb1501b` 不是有效 Secp256k1 压缩公钥（x 坐标不在曲线上）。`NewPublicKeyFromStringRelaxed` 先尝试 hex 失败后回退 base58，最终只抛出 `invalid base58 string`，误导用户。
- 修复：修改 `gosdk-develop/crypto/publickey.go` 的 `NewPublicKeyFromStringRelaxed`，hex 和 base58 都失败时返回合并错误信息，保留 hex 解析失败的真实原因。
- 涉及文件：`gosdk-develop/crypto/publickey.go`。

## 多指令打包上链：后端接口 + 前端批量配置（参考 gosdk-develop/example/multi_ix_demo）

- 背景：用户参考 `gosdk-develop/example/multi_ix_demo/main.go`，希望 API 服务支持多条指令打包成单笔交易上链（原子执行），并让前端用户好配置参数。

## BalanceOf"账户不存在"根因：前端 Address 参数预填 bug（已修复，commit 73de936）

- 用户批量打包 `ClaimFaucet + BalanceOf` 报 `账户不存在`，单独领水后仍报错。查 preview-server.log 时间线：
  - 16:34:33 单独领水成功（txHash=a273...）
  - 16:34:40 批量仍失败，错误里 `token: 76jzigtaQbiezJYcA51dAkSWtLY` —— **token 被填成了账户自己的地址**！
- 根因：`buildIDLArgInput` 对所有 Address 类型参数都预填活跃账户地址。`BalanceOf.token` 是 Address 类型 → 被预填为账户地址 → 链端查"token=账户地址"当然账户不存在。
- 验证：领水后正确填 MIL token 地址 `M11on1111111111111111111111`（27 个 1）查 BalanceOf 返回 9999989780，链路正常。
- 修复（static/js/app.js buildIDLArgInput）：地址类参数按语义分流——
  - signer/账户类（role=signer 或参数名匹配 from/owner/holder/claimer/sender/payer/spender/subject/admin/freezer/to/recipient/account）→ 预填活跃账户地址
  - 资源地址类（token 等）→ 优先 IDL 示例值；无示例时兜底填 MIL token 地址 `M11on1111111111111111111111`（用户明确要求 token 参数自动填 MIL）
- 额外确认：同笔交易内 ClaimFaucet+BalanceOf 模拟时，BalanceOf 看不到 ClaimFaucet 刚创建的资源（State=2/512 账户不存在）——链上指令间状态隔离，领水与查询应分两笔交易。
- 前端是静态文件，改 app.js 刷新页面即生效，无需重启 Go 服务。
