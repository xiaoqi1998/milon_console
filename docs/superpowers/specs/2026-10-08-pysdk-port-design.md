# milon-go-sdk → milon-python-sdk 全量移植设计

- 日期：2026-10-08
- 状态：已获用户批准（分批全量交付 + 移植 idlgen 生成器）
- 源：`gosdk-develop/`（103 个 Go 文件，约 5.6 万行，其中 `gen/idl_gen.go` 3.3 万行为机器生成代码）
- 目标：`pysdk-develop/src/milon_sdk/`（包名 `milon_sdk`，发布名 `milon-python-sdk`）

## 1. 总体原则

- 移植规范主体是既有的 `pysdk-develop/CONVENTIONS.md`（命名映射、错误处理、
  位宽校验、密码学库对应关系、测试规则），本设计不重复其内容，只补充批次划分、
  生成器设计与验收标准。
- 逐文件、逐函数对译：类型/类保留 Go PascalCase，函数/方法/字段 snake_case，
  构造函数 `NewXxx` → `new_xxx`，常量 UPPER_SNAKE，枚举 `enum.IntEnum`。
- 错误处理：Go `(value, error)` → Python 直接 `raise`；`%w` 包装 → `raise ... from`。
- 每个 Go `*_test.go` 必须移植为 `tests/<pkg>/test_<file>.py`，测试向量逐字保留，
  测试全绿是"功能一致"的硬证据。

## 2. 包依赖拓扑（决定批次顺序）

```
postcard(已完成) → types(已完成) → crypto → api → provider → lib
                                                  ├→ helper
                                                  └→ gen(生成器)
根目录(client/rpcClientV1/...) 依赖以上全部，最后做
```

## 3. 分批计划（8 批，每批独立可验证、可回滚）

| 批次 | 内容 | 验证标准 |
|---|---|---|
| 批0 | 补 postcard（`postcard_test.go` 274 行）与 bitbap（`bitmap_test.go` 192 行）的 pytest 移植 | 存量代码测试全绿，先把已有实现锁住 |
| 批1 | `crypto/` 7 文件：address、error、hash_domain、publickey、secretkey、signature、fn_dsa512；含 `_fndsa` 纯 Python 移植（FN-DSA-512，接口契约见 CONVENTIONS.md） | crypto/test 测试向量对拍全绿（含四曲线地址派生、BLS、FN-DSA） |
| 批2 | `api/` 12 文件：视图/RPC 请求响应类型 | api/test 测试绿 |
| 批3 | `provider/`：types、idlTypeResolver、registry、provider.go；拷贝 `provider/IDL/*.json` 进包数据 | provider/registry/resolver 测试绿 |
| 批4 | `lib/` 6 文件：transaction、transactionBuilder、accountSignature(Build)、rpcRequest/Response | lib/test 测试绿 |
| 批5 | `helper/` 6 文件 + 根目录 7 文件（client、rpcClientV1、blockStream、framedHistory、network、printFramedHistory、resolveResourcePaths） | 单测绿；`new_client` 可构造 |
| 批6 | `gen.go`（RegisterApp/BindAll）对译 + 编写 `tools/idlgen.py` 生成器，从 `provider/IDL/index.json` 生成 `src/milon_sdk/gen/idl_gen.py` | Go↔Python 生成物结构对账（app 数、instruction 数、判别器集合）全等；生成物可 import、builder 可 encode |
| 批7 | 总验收：全量 pytest + 生成器幂等检查（重跑 diff 为空）+ 可选 devNet 冒烟（new_client + 查余额） | 全绿 |

批内顺序按 TDD：先移植 Go 测试（红），再译实现（绿）。批4 与批5 的 helper 部分
无相互依赖，实际执行时可穿插。

## 4. idlgen 生成器设计（批6）

- 独立脚本 `pysdk-develop/tools/idlgen.py`，不属于 SDK 运行时依赖。
- 输入：`src/milon_sdk/provider/IDL/index.json`；输出：`src/milon_sdk/gen/idl_gen.py`。
- 输出文件头：`# Code generated by milon idlgen. DO NOT EDIT.`
- 生成物对齐 Go 侧三件套：
  1. `DEFAULT_IDLS` 常量（全部 IDL 内联，对齐 JS SDK 的 DEFAULT_IDLS）；
  2. 类型化 instruction builder：`gen.TOKEN.CLAIM_FAUCET.args(...).encode()`，
     app 对象为包级变量 UPPER_SNAKE；
  3. 自定义类型 dataclass + `decode_view`（视图响应体直接解码）。
- `src/milon_sdk/gen/gen.py` 手写：模块级 binder 注册表 + `threading.RLock`，
  `register_app`/`bind_all` 语义与 Go 一致（`new_client` 每次重建后重绑）。
- gosdk 侧 IDL 升级时换 index.json 重跑生成器即可同步 Python 侧。

## 5. 工程约定

- `pyproject.toml` 维持现状（依赖已齐：blake3/coincurve/cryptography/py_ecc/base58/requests/grpcio）。
- 运行环境：Windows 下 `/d/miniconda/python.exe`；Git Bash 临时文件传给 Windows
  Python 前用 `cygpath -m` 转换路径。
- `__pycache__` 加入 `.gitignore`。

## 6. 风险与对策

- **FN-DSA-512 纯 Python 移植**（批1 最重）：go-fn-dsa@v0.2.0 源码在本机 Go module
  cache，逐函数对译 + Go 侧已知测试向量对拍；向量不过时最小复现排查，禁止盲改。
- **BLS12-381 与 blst 行为对齐**：py_ecc basic 方案 + 自实现 EIP-2333 KeyGen 与
  ZCash 压缩序列化（48B/96B，flags 与 blst 一致），用 Go 侧跨语言向量锁定。
- **生成物对账**：批6 必须写 Go `idl_gen.go` ↔ Python `idl_gen.py` 结构对账脚本，
  防止生成器漏项。
